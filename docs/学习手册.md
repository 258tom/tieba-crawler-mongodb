# 第一部分：30 分钟跑起来

## 1.1 你需要准备什么

| 需要的东西 | 说明 | 检查方式 |
|---|---|---|
| Python 3.10+ | 项目用了 `X \| None` 语法 | `python --version` |
| MongoDB 6.0+ | 数据库本体，本地或远程都行 | 见 1.3 |
| `.venv\` 虚拟环境 | 装了 aiotieba / pymongo | `python -m pip list` |
| BDUSS | 贴吧登录凭据，见 [README 步骤 4](../README.md#4-配置凭据必需) | 爬取时才需要 |

## 1.2 四步跑通

```bash
# 第 1 步：启动数据库（三选一，见 1.3）
mongod --dbpath /your/data/path
#   或者用 Docker：docker run -d -p 27017:27017 --name mongo mongo:8.0

# 第 2 步：准备凭据（只需一次）
cp .env.example .env      # Windows: copy .env.example .env
#   然后编辑 .env 填上 TIEBA_BDUSS

# 第 3 步：爬取数据（真实访问贴吧，BDUSS 得还有效）
python crawler.py --fname 弱智 --max-page 32

# 第 4 步：查数据
python query.py

# 第 5 步（可选）：启动 HTTP 接口
python api_server.py
#   浏览器打开： http://127.0.0.1:8000/
```

> 💡 **只想先验证流程、不想联网？** 跑 `python crawler.py --offline`，
> 它用假数据走完整的入库链路，不需要 BDUSS。

## 1.3 启动数据库的三种方式

MongoDB 是个**进程**，不是系统服务 —— 这点很重要，它意味着**关掉就停、开机不自启**。

```bash
# 方式一：本地已装 MongoDB（最直接）
mongod --dbpath /your/data/path

# 方式二：Docker（最省事，不用装）
docker run -d -p 27017:27017 --name mongo mongo:8.0

# 方式三：MongoDB Atlas 云端免费实例
#   把连接串填进 .env 的 MONGO_URI（形如 mongodb+srv://...）
```

> ⚠️ 用前台方式跑 `mongod` 时，**那个窗口要一直开着**。
> 关掉窗口 = 数据库停止，之后所有操作都会报 `ServerSelectionTimeoutError`。
> 想让它后台常驻，用 `--fork --logpath`（Linux/macOS）或注册成 Windows 服务。

### 数据库到底在跑吗？三条命令

```powershell
# Windows PowerShell
Test-NetConnection 127.0.0.1 -Port 27017 | Select-Object TcpTestSucceeded    # True 就是通了
Get-Process mongod | Select-Object Id, Path                                  # 有没有进程
```

```bash
# 跨平台：直接用驱动 ping（最权威）
python -c "from pymongo import MongoClient; print(MongoClient('mongodb://127.0.0.1:27017', serverSelectionTimeoutMS=3000).admin.command('ping'))"
```

## 1.4 改配置（不用动代码）

配置都写在项目根目录的 `.env` 里，**改完不需要动任何 Python 代码**：

```ini
# .env
TIEBA_BDUSS=你的BDUSS
MONGO_URI=mongodb://127.0.0.1:27017   # 连接地址
MONGO_DB=tieba                        # 数据库名
MONGO_COLLECTION=threads              # 集合名
```

优先级是 **真实环境变量 > `.env` 文件 > 代码里的默认值**，
所以临时想换一台数据库，直接设环境变量就行（不用改 `.env`）：

```powershell
# Windows PowerShell（只对当前窗口有效）
$env:MONGO_URI = "mongodb://127.0.0.1:27018"
python query.py stats
```

```bash
# macOS / Linux
MONGO_URI="mongodb://127.0.0.1:27018" python query.py stats
```

# 第二部分：学习路线图（重点）

这个项目麻雀虽小，五脏俱全：**异步编程 + 网络爬虫 + 数据建模 + 数据库 + HTTP 接口**。
下面按依赖顺序分 6 个阶段，**每阶段都有明确目标和验证方法**，做完一个再进下一个。

> 学法建议：**不要从头到尾读代码**。先按阶段跑通、观察现象，再回头读那一块代码。
> 每阶段先问自己"我现在能解释这个现象为什么发生吗"，解释不了再去看源码。

## 阶段 0：先把环境搞明白（约 30 分钟）

**要解决的问题**：为什么我改了代码没生效？这个 `.venv` 是干嘛的？

| 要搞清楚的概念 | 怎么做 |
|---|---|
| 虚拟环境 | `.venv\Scripts\python.exe` 和系统 `python` 是两个不同的 Python。**永远用 `python` 跑本项目** |
| 依赖装在哪 | `python -m pip list`，看 `aiotieba` / `pymongo` 的版本 |
| 进程 vs 服务 | `mongod` 是一个**进程**，不是系统服务。所以关窗口就停、开机不自启 |

**验证**：能解释"为什么我必须双击 `.cmd` 而不能双击 `.ps1`"（答案：执行策略 Restricted）。

## 阶段 1：数据长什么样（约 1 小时）

**要解决的问题**：aiotieba 爬回来的东西到底是个什么对象？

**这样做**：

```powershell
# 看单条数据的全部字段（最直观）
python query.py show 8005359738

# 看原始 Python 对象
python -c "import asyncio, aiotieba as tb; print(asyncio.run(tb.Client('你的BDUSS').get_threads('弱智', 1)))"
```

**要理解的关键点**：aiotieba 返回的 `Thread` 是个 **dataclass**，字段分三类：

- 扁平字段：`tid` `title` `view_num` `reply_num` `create_time`
- 嵌套对象：`user`（作者信息）、`contents`（正文碎片）
- 枚举：`type`（`ThreadType.HELP` 这种）

**为什么重要**：这直接决定了它在 MongoDB 里怎么存（见阶段 4）。MongoDB **没有 JOIN**，所以 `user` 只能嵌进去。

**验证**：说出 `show` 命令输出里哪些字段是嵌套的。

## 阶段 2：异步编程（约 2 小时，这是最陡的一段）

**要解决的问题**：8 个协程同时在跑，为什么不会互相打架？

**读代码顺序**：

1. `demo_asyncio_basic.py` —— 最简形态，看懂 `async def` / `await` / `asyncio.run`
2. `demo_asyncio_queue.py` —— 生产者-消费者模型：`asyncio.Queue` + `asyncio.gather`
3. `crawler.py` —— 在 2 的基础上加了数据库写入

**要理解的关键点**：

| 概念 | 在本项目里的体现 |
|---|---|
| `async def` / `await` | `await client.get_threads(...)` —— 等网络时不阻塞其他协程 |
| 生产者-消费者 | `producer()` 往队列塞页码，`worker()` 从队列取页码去爬 |
| `asyncio.Queue(maxsize=8)` | 缓冲区满 8 个时生产者会被阻塞，**这是背压机制**，防止任务堆积 |
| `asyncio.gather` | 把 8 个 worker 和 1 个 producer 一起并发跑起来 |
| `asyncio.wait_for` | `timeout=1` 秒取不到任务就检查要不要退出 —— **这是退出机制**，不然 worker 会永远等下去 |

**那个"为什么用 `is_running` 标志位"**：worker 靠"队列超时 + 标志位为 False"退出。如果不用标志位，worker 无法区分"暂时没任务"和"活干完了"。可以试试把它改成 `None` 哨兵值（sentinel），体会两种写法的差别。

**验证**：把 `WORKER_NUM` 从 8 改成 1 再改成 16，对比耗时。能解释为什么不是线性加速吗？（提示：百度接口有速率限制，而且 1 个协程时网络延迟完全串行了）

## 阶段 3：MongoDB 基本操作（约 1 小时）

**要解决的问题**：没有建表语句，数据存哪去了？

**读代码**：`mongo_store.py` 的 `ThreadStore` 类。

**用 `query.py` 交互模式边玩边学**（比看文档快）：

```
> help
> indexes                       看索引
> explain {"view_num":{"$gt":100000}}   看查询有没有走索引
> find {"$or":[{"view_num":{"$gt":100000}},{"is_good":true}]}
```

**核心概念对照**（熟悉 MySQL 的话）：

| MySQL | MongoDB | 本项目 |
|---|---|---|
| 数据库 | 数据库 | `tieba` |
| 表 | **集合 collection** | `threads` |
| 行 | **文档 document**（就是 dict） | 一条帖子 |
| 列 | 字段 field（**可以每条不一样**） | `title` `view_num` … |
| 主键 | `_id` | 自动生成的 `ObjectId` |
| 索引 | 索引 | 6 个（见 `mongo_store.py`） |
| `GROUP BY` | 聚合管道 `aggregate` | `stats()` / `cmd_daily` |

**最关键的一条**：MongoDB **不用建表**。往 `tieba.threads` 塞第一个文档时，数据库和集合会自动创建。

**验证**：用 `query.py` 的 `explain` 命令，对比 `{"fname":"弱智"}`（走索引）和 `{"is_good":true}`（没索引）的执行计划差异。

## 阶段 4：数据建模（约 1 小时）

**要解决的问题**：为什么用 `tid` 去重而不是直接插入？

**读代码**：`mongo_store.py` 的 `doc_from_thread()` 和 `save_threads()`。

**这是本项目最有价值的一段设计**。三个决策：

| 决策 | 为什么这么做 | 不这么做会怎样 |
|---|---|---|
| 用 `tid` 做唯一键 + **upsert** | 爬 10 次不会产生 10 条重复数据，浏览量这类变化字段还会被刷新 | 用 `insert_many` 第二次爬就撞 `DuplicateKeyError` |
| `$setOnInsert: {first_crawled_at}` | 记录"第一次见到这条帖子"的时间，后续更新不覆盖 | 会被每次爬取刷新，丢掉历史信息 |
| 存 `create_dt`（Date 类型）+ `posted_at_text` | 原始时间戳留着好排序；Date 类型能做 `$dateToString` 按天分组；文本版给人看 | 只有时间戳的话，按天统计得自己写转换 |

**动手实验**（强烈建议做）：

```powershell
# 连爬两次，观察第二次的统计
python crawler.py
python crawler.py
# 第二次应该是 "新增 0"（数据没变），总数不变 —— 这就是幂等
```

**验证**：`test_e2e_mongodb.py` 里那条 "重复写同一批：新增 0 条" 的断言，能讲清它证明了什么。

## 阶段 5：HTTP 接口 + 工程化（约 2 小时）

**要解决的问题**：为什么用标准库 `http.server` 而不用 FastAPI？

**答案**：你的环境没装 FastAPI，而装包在这个网络环境很麻烦（HTTPS 不通）。`api_server.py` 零第三方依赖，拿到就能跑。以后迁到 FastAPI 只需把路由逻辑搬过去，换一层壳。

**要理解的关键点**：

| 点 | 位置 | 为什么 |
|---|---|---|
| 同步客户端 | `api_server.py` 顶部 | `ThreadingHTTPServer` 是多线程的，`MongoClient` 同步版线程安全且自带连接池 |
| 异步客户端 | `mongo_store.py` | 爬虫是 asyncio，必须用 `AsyncMongoClient`，否则阻塞事件循环 |
| 排序字段白名单 | `SORTABLE` 字典 | **不能让用户直接传字段名**，否则可以构造慢查询打垮数据库 |
| `to_jsonable()` | `api_server.py` | MongoDB 返回的 `ObjectId` / `datetime` 不能直接 `json.dumps` |

**验证**：故意传 `?sort=; drop db`，看接口是否返回 400（`test_api_server.py` 里就有这条断言）。

## 阶段 6：可视化入门（约 2 小时）

第一个可视化图建议用 **matplotlib**，因为它最基础、概念最少。
`query.py daily 14` 已经在终端里画了柱状图（`█` 字符），把它搬到窗口里就成图了。

具体建议见[第四部分](#第四部分可视化建议)。

## 学完之后可以做什么（进阶方向）

想继续深入的话，按难度排序：

1. **爬评论** —— 用 `tb.Client.get_posts(tid)`，数据量级立刻涨一个数量级，会逼你认真考虑索引和分页
2. **增量爬取** —— 只爬"比上次更新更新的"帖子（`last_time > 上次爬取时间`），体会状态管理
3. **改造成 FastAPI** —— 加依赖注入、自动生成的 OpenAPI 文档、Pydantic 校验
4. **加定时任务** —— 用 `schedule` 或 Windows 计划任务，每小时自动爬一次（注意 BDUSS 失效的处理）
5. **数据量大之后** —— 分页游标（别用 `skip`，数据量大时它很慢）、`$text` 全文索引、读写分离

# 第三部分：方便地查询数据

## 3.1 交互模式（最方便，推荐日常用）

```powershell
python query.py
```

进去之后像用 mongosh 一样，**直接输入吧名就能切换**：

```
  ===== 贴吧数据查询（交互模式）=====
  共有 1,044 条数据，来自 2 个吧：中国人口, 弱智

  [中国人口] > 弱智                ← 切到"弱智"吧
  [弱智] > top 5                   ← 看浏览量 Top5
  [弱智] > daily 14                ← 最近14天发帖量（终端柱状图）
  [弱智] > find {"view_num":{"$gt":1000000}}
  [弱智] > all                     ← 不限吧
  [弱智] > exit
```

完整命令（进去后输入 `help` 也能看）：

| 命令 | 作用 |
|---|---|
| 直接输入吧名 | 切换当前吧（如 `弱智`）；`all` 表示不限 |
| `stats` | 总览：每个吧多少帖、总浏览量 |
| `top 10` | 浏览量 Top10 |
| `latest 10` | 最新发帖 |
| `hot 10` | 回复率高的热帖 |
| `recent 7` | 最近 7 天的帖子 |
| `search 房价` | 标题含关键词 |
| `author 某网友` | 某作者的帖子（注意 `user` 是嵌套字段） |
| `daily 14` | 最近 14 天每天发帖量 + 柱状图 |
| `find {...}` | **原生 MongoDB 查询**（学语法最有用） |
| `show 8005359738` | 看某条帖子的**完整文档**（学数据结构最有用） |
| `indexes` | 查看索引和集合大小 |
| `explain {...}` | 查看查询计划，确认走没走索引 |

## 3.2 命令行模式（适合写脚本、导出）

```powershell
python query.py top 10
python query.py recent 3
python query.py search 房价 --limit 5
python query.py top 100 --min-views 100000

```

## 3.3 MongoDB 查询语法速查

这是**最值得花时间学**的部分。`find` 里传的就是这个：

| 操作符 | 含义 | 例子 |
|---|---|---|
| `$gt` `$gte` | 大于 / 大于等于 | `{"view_num": {"$gt": 10000}}` |
| `$lt` `$lte` | 小于 / 小于等于 | `{"reply_num": {"$lte": 10}}` |
| `$ne` | 不等于 | `{"fname": {"$ne": "弱智"}}` |
| `$in` | 在列表里 | `{"fname": {"$in": ["弱智", "中国人口"]}}` |
| `$regex` | 正则 / 模糊匹配 | `{"title": {"$regex": "房价"}}` |
| `$exists` | 字段存在 | `{"create_dt": {"$exists": true}}` |
| `$and` `$or` | 逻辑组合 | `{"$or": [{"view_num": {"$gt": 100000}}, {"is_good": true}]}` |

**嵌套字段用点号**（这是最容易忘的一点）：

```javascript
{"user.user_name": "某网友"}      // 作者名在 user 里面
{"user.level": {"$gte": 10}}      // 作者等级
```

**排序和分页**：

```javascript
.sort({"view_num": -1})   // -1 降序，1 升序
.skip(20).limit(10)       // 跳过 20 条取 10 条 —— 只适合小数据量
```

> ⚠️ `skip` 在数据量大时很慢（它要真的数过去）。生产环境用"游标分页"：
> 记住上一页最后一条的 `view_num`，下一页查 `{"view_num": {"$lt": 上一页最后那个值}}`。

## 3.4 直接在 Python 里查

```python
import asyncio
from mongo_store import ThreadStore

async def main():
    async with ThreadStore() as store:
        print("总数:", await store.count("弱智"))

        # 封装好的常用查询
        for doc in await store.top_by_views("弱智", limit=10):
            print(doc["view_num"], doc["title"])

        # 想自定义就用原生 pymongo 语法
        cursor = store.collection.find({"view_num": {"$gt": 100000}}).sort("view_num", -1).limit(5)
        async for doc in cursor:
            print(doc["tid"], doc["title"])

asyncio.run(main())
```

# 第四部分：可视化建议

> 说明：**以下是建议，我没有实现**。你自己挑一个方向做，这也是最好的练习。

## 4.1 先说数据准备（这一步比选工具重要）

可视化的难点不在画图，在**把数据整理成"每行一条记录"的表格**。好消息是 `query.py --export` 已经能导出了：

```powershell
python query.py top 200 --export data/top200.csv
```

`daily` 那种"按天分组"的数据需要写聚合管道。**思路**（`query.py` 的 `cmd_daily` 里已有现成实现，可以照抄）：

```python
pipeline = [
    {"$match": {"create_time": {"$gte": 起点时间戳}}},
    {"$group": {
        "_id": {"$dateToString": {"format": "%Y-%m-%d", "date": "$create_dt"}},
        "posts": {"$sum": 1},
        "views": {"$sum": "$view_num"},
    }},
    {"$sort": {"_id": 1}},
]
```

关键在于我们存了 `create_dt` 这个 **Date 类型**字段（而不只是时间戳），所以 `$dateToString` 能直接按天/按月格式化。这就是阶段 4 里说的"数据建模影响后面的分析能力"。

## 4.2 三条路线，按上手难度排序

### 路线 A：Excel（零代码，10 分钟出图）

1. `query.py --export data/out.csv`
2. 双击用 Excel 打开（BOM 已处理，中文不乱码）
3. 选中数据 → 插入 → 数据透视表 / 图表

**适合**：快速看一眼数据、给不写代码的人看。
**能做什么**：柱状图（浏览量 Top20）、散点图（浏览量 vs 回复数）、时间趋势线。
**局限**：数据超过几十万行 Excel 会卡；不可重复，下次数据更新要手动重做。

### 路线 B：matplotlib（Python 里最基础，强烈建议第一次用这个）

优点：概念最少，只需知道 `plot` / `bar` / `scatter` / `show`，而且和你现在写的 Python 是同一套东西。

**建议先画这三张图**：

| 图 | 类型 | 说明什么 |
|---|---|---|
| 浏览量分布直方图 | `hist` | 数据是不是"少数帖子爆火、多数很冷"的长尾分布（大概率是） |

# 第五部分：设计原理

## 5.1 数据是怎么存的

MongoDB **没有 JOIN**，所以作者信息直接嵌在帖子文档里，而不是另开一张用户表。一条文档长这样：

```json
{
  "_id": ObjectId("..."),
  "tid": 987654321,                    // 主题帖 id，拿它当唯一标识做去重
  "fname": "中国人口",                  // 所在吧名
  "fid": 123456,
  "title": "测试标题：房价会跌吗",
  "view_num": 88888,                   // 浏览量
  "reply_num": 666,
  "share_num": 5,
  "agree": 99,
  "disagree": 2,
  "type": 1,                           // ThreadType 枚举，存为整数
  "is_good": false,                    // 是否精品帖
  "is_top": false,                     // 是否置顶帖
  "create_time": 1767225600,           // 发帖时间（10位秒级时间戳，排序用）
  "last_time": 1767312000,
  "create_dt": ISODate("2026-01-01T00:00:00Z"),   // 额外加的 Date，供聚合按天分组
  "posted_at_text": "2026-01-01 08:00:00",        // 额外加的，人眼直接看
  "crawled_at": ISODate("..."),                   // 本次爬到的时间
  "first_crawled_at": ISODate("..."),             // 第一次爬到的时间（更新不覆盖）
  "source": "get_threads/pn=3",                   // 数据来自第几页
  "user": {                            // 作者信息，嵌套（MongoDB 没有 JOIN）
    "user_id": 111,
    "user_name": "某网友",
    "nick_name_new": "昵称呀",
    "level": 7,
    "gender": 0
  },
  "contents": {                        // 正文的结构化碎片
    "texts": [{"text": "正文第一段"}],
    "imgs": [{"src": "...", "big_src": "...", "hash": "..."}],
    "emojis": [], "ats": [], "links": []
  }
}
```

## 5.2 六个索引，各自管什么

| 索引名 | 字段 | 用途 |
|---|---|---|
| `uniq_tid` | `tid`（**唯一**） | 去重的基石，保证一个帖子只有一条文档 |
| `fname_create` | `fname` + `create_time`↓ | "某个吧最新的帖子" |
| `fname_view` | `fname` + `view_num`↓ | "某个吧浏览量排行" ← 最常用 |
| `fname_reply` | `fname` + `reply_num`↓ | "某个吧回复数排行" |
| `create_time` | `create_time`↓ | 不限吧的全局时间排序 |
| `title_text` | `title`（全文索引） | 标题全文搜索 |

**为什么字段顺序重要**：`fname + view_num` 这个组合索引能支持"先按 fname 筛选、再按 view_num 排序"的查询。如果反过来建 `view_num + fname`，那"查某个吧的帖子"就用不上它了。这叫**最左前缀原则**，和 MySQL 一样。

**验证索引有没有生效**：

```powershell
python query.py explain '{\"fname\":\"弱智\"}'
# 输出里看到 IXSCAN = 走了索引；COLLSCAN = 全表扫描，该加索引了
```

## 5.3 三个容易踩的技术点

**① `upsert` 而不是 `insert_many`**

```python
UpdateOne({"tid": tid},
          {"$set": doc, "$setOnInsert": {"first_crawled_at": now}},
          upsert=True)
```

`upsert` = "有这个 tid 就更新，没有就插入"，天然幂等。8 个协程并发爬到同一个帖子也不会冲突。
用 `insert_many` 第二次爬就会撞 `uniq_tid` 唯一索引报 `DuplicateKeyError`。

**② 异步驱动的 `aggregate()` 和 `find()` 用法不一样**

```python
# find() —— 直接返回游标，不用 await
cursor = collection.find({...})
async for doc in cursor: ...

# aggregate() —— 返回的是协程，必须先 await！
cursor = await collection.aggregate(pipeline)   # 漏掉 await 就报：
async for doc in cursor: ...                    # TypeError: 'async for' requires
                                                # an object with __aiter__ method,
                                                # got coroutine
```

同一个库里两个方法的 API 不一致，这是 pymongo 异步版的设计。**这是我实际跑出这个错才发现的。**

**③ `project` 是白名单，新算的字段要显式加进去**

```python
pipeline = [
    {"$addFields": {"reply_rate": {"$divide": ["$reply_num", "$max": ["$view_num", 1]]}}},
    {"$project": {**BRIEF, "reply_rate": 1}},   # 不写这一行，reply_rate 会被过滤掉
]
```

`$project` 只保留列出的字段。`reply_rate` 是 `$addFields` 新加的，所以它也得列进去，否则算完了却取不到（我一开始就漏了这行，导致"热帖"显示不出回复率）。

## 5.4 驱动选型：别用 motor

`motor` 这个异步驱动**已经被官方废弃**（你环境里装的 `motor 3.7.0` 就是废弃版）。官方推荐直接用 `pymongo` 自带的异步客户端——`pymongo` 从 **4.9** 开始提供 `pymongo.asynchronous`，你的是 `4.18.0`，完全够用。

```python
from pymongo import AsyncMongoClient      # 异步（爬虫用）
from pymongo import MongoClient           # 同步（接口用）
```

## 5.5 踩过的真实 bug：正文带链接的帖子会让爬虫崩溃

这个是**运行时**才暴露的问题，值得单独讲，因为它演示了"数据内容决定代码能不能跑"这件事。

### 现象

爬"中国人口""弱智"都很正常，换成"营山二中"就崩：

```
bson.errors.InvalidDocument: Invalid document: cannot encode object:
URL('http://tieba.baidu.com/mo/q/checkurl?url=http://www.memorychina.com&urlrefer=...'),
of type: <class 'yarl.URL'>
```

### 原因

贴吧帖子的正文里如果**带链接**，aiotieba 会把链接解析成一个 `yarl.URL` 对象（不是字符串）：

```python
@dcs.dataclass
class FragLink:
    text: str = ""          # 原链接（字符串）
    title: str = ""         # 链接标题
    raw_url: yarl.URL = ...  # ← 解析后的对象，bson 存不了
```

`dataclasses.asdict()` 会忠实地把这个对象原样转进字典，而 bson 只支持有限的基础类型，遇到 `yarl.URL` 就抛异常。

**致命的地方在于**：`save_threads` 是**一页 30 条一起提交**的，其中**任何一条**编码失败就会让**整页**的 `bulk_write` 失败，异常直接冒泡出去，整个爬虫挂掉。也就是说 **30 条里只要有 1 条带链接，这一页全丢**。

### 实测数据

| 吧 | 帖子数 | 带链接的帖子 | 结果 |
|---|---|---|---|
| 弱智 | 89 | 0 | 正常 |
| 中国人口 | 955 | 0 | 正常 |
| 营山二中 | 849 | **9** | **崩溃** |

"营山二中"这种校园吧里全是招生广告、兼职、外链，所以链接帖特别多。**这也解释了为什么同样的代码在不同吧上表现不一样。**

### 怎么修的

在 `mongo_store.py` 加了一个通用的类型清洗 `_sanitize()` / `make_bson_safe()`：

1. 递归遍历文档，遇到 bson 支持的基础类型就留着
2. 遇到 `NaN` / `Infinity` 这种浮点值 → 转成 `None`
3. **遇到其它任何类型（`yarl.URL` 等）→ 转成字符串**

第 3 条用"统一转字符串"而不是"专门处理 `yarl.URL`"是刻意的：以后 aiotieba 升级引入新的第三方类型，也不会再让爬虫崩掉。

另外在 `save_threads` 里加了兜底：单条帖子编码失败只记一条 `warning` 并跳过**这一条**，不再让整页失败。

### 怎么自己排查这类问题

想知道一个对象里哪些字段的类型 bson 不支持，就用 `BSON.encode()` 试一下：

```python
from bson import BSON
try:
    BSON.encode(doc)          # doc 是转换后的字典
    print("OK")
except Exception as exc:
    print(type(exc).__name__, exc)    # 会直接告诉你是哪个类型
```

**这个 bug 的教训**：`dataclasses.asdict()` 转出来的字典**不等于**可以直接存进数据库的文档。第三方库字段里的自定义类型需要通过"序列化边界"时做一次清洗。写别的存储层（写 JSON、写 SQL）时也是同一个道理——`json.dumps` 同样会被 `yarl.URL` 卡住。

# 第六部分：疑难杂症

## 6.1 启动相关

| 现象 | 原因 | 解决 |
|---|---|---|
| `ServerSelectionTimeoutError ... 积极拒绝` | **数据库没在跑**（最常见） | 先启动 `mongod`，并确认那个窗口/进程一直活着 |
| **明明启动成功，过一会数据库没了** | **前台窗口被关掉了** | 前台运行 = 关窗口即停止。要常驻请用 `--fork --logpath` 或系统服务 |
| `FileNotOpen: Can't initialize rotatable log file` | 日志文件打不开（权限或目录不存在） | 确认 `--dbpath` / `--logpath` 指向的目录存在且可写 |
| `FileRenameFailed: Could not rename preexisting log file` | mongod 想轮转旧日志但改名失败 | 加 `--logappend` |
| `Invalid command: true` + 一大篇帮助 | `--logappend true` 写错了 | `--logappend` 是纯布尔开关，**不能带任何值** |
| `option '--logappend' does not take any arguments` | `--logappend=true` 也是错的 | 只写 `--logappend` |
| 端口 27017 被占用 | 已经有一个 mongod 在跑 | `Get-NetTCPConnection -LocalPort 27017 -State Listen`（Windows）或 `lsof -i :27017` 看是谁 |
| `Authentication failed` | URI 里带了不对的账号密码 | 本地默认**不开**认证，写 `mongodb://127.0.0.1:27017` 就行；Atlas 要填对用户名密码并加 `?authSource=admin` |
| 中文在 Windows 控制台显示成乱码 | 控制台代码页不是 UTF-8 | 见 [README FAQ](../README.md#faq) 里的 `PYTHONIOENCODING` 设置 |

## 6.2 下载安装包踩过的坑

打包下载 MongoDB 时遇到过的两个问题，换环境也可能碰到：

**① HTTPS 不通但 HTTP 能通** —— 某些代理环境里 `https://fastdl.mongodb.org` 一律 TLS 握手失败，
但 `http://` 能拿到真文件。判断"拿到的是不是真文件"可以看返回内容开头的 ZIP 魔数 `PK\x03\x04`。

**② 下载被中途掐断，而且脚本误报"下载完成"** —— 755 MB 的包只下到 321 MB（42%）就断了。
截断的 ZIP 有两个识别方法：

1. 尾部没有 ZIP 结束标记 `PK\x05\x06`
2. `zipfile.ZipFile(path)` 直接报 `BadZipFile`

正确做法是**断点续传**（`Range` 请求头）+ **完整性校验** + 自动重试，别指望一次下完。

## 6.3 代码相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `bson.errors.InvalidDocument: cannot encode object: URL('http://...'), of type: <class 'yarl.URL'>` | **正文里带链接的帖子**：aiotieba 的 `FragLink` / `FragTiebaPlus` 把链接解析成 `yarl.URL` 对象，bson 不认识 → 整页写入失败、爬虫崩溃 | 已修复：`mongo_store.py` 的 `make_bson_safe()` 会把这类对象统一转成字符串。详见 [5.5](#55-踩过的真实-bug正文带链接的帖子会让爬虫崩溃) |
| `TypeError: 'async for' requires an object with __aiter__ method, got coroutine` | `aggregate()` 忘了 `await` | `cursor = await collection.aggregate(...)` |
| 聚合算出的字段取不到（是 `None`） | `$project` 把它过滤掉了 | 把新字段加进 `$project`：`{**BRIEF, "新字段": 1}` |
| `DuplicateKeyError: E11000` | 撞了 `uniq_tid` 唯一索引 | 用 `upsert`，别用 `insert_many` |
| `DocumentTooLarge: BSON object too large` | 单条文档超过 16 MB | `save_threads` 已做大小检查并跳过，日志里有 skipped 计数 |
| `OSError: [Errno 22] Invalid argument` | `timedelta(days=36500)` 让 datetime 溢出 | 天数太大就别加时间条件（`query.py` 的 `build_query` 已处理） |
| `SyntaxError: no binding for nonlocal 'is_running' found` | `nonlocal` 被缩进进了 for 循环 | 必须写在函数体第一层 |
| `RuntimeError: 拿不到 TIEBA_BDUSS ...` | 没有配置凭据 | 复制 `.env.example` 为 `.env` 并填上 BDUSS |

## 6.4 安全提醒

**BDUSS 等同于你的贴吧账号凭据**，泄露的后果是别人可以用你的号发帖、删帖。

本项目所有凭据都从 `.env` / 环境变量读取，**代码里没有任何硬编码密钥**：

```python
from tieba_env import require_bduss

bduss = require_bduss()      # 取不到会抛异常，并附上完整的获取步骤
```

如果你在别处还写过硬编码的 BDUSS，请务必：
1. 把它移到 `.env`（该文件已在 `.gitignore` 中）
2. **去贴吧重新登录一次**，让泄露的那个 BDUSS 失效
3. 用 `git log -p` 检查历史提交里有没有残留（历史提交也会被公开看到）

另外 `api_server.py` 默认只监听 `127.0.0.1`（仅本机可访问），这是个好默认值，
**不要随便改成 `0.0.0.0`** —— 那等于把数据接口暴露到局域网，而它目前没有任何鉴权。
